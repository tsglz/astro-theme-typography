这个问题我其实很久之前就在考虑了，到底什么样的技术可以防住 agent 进行样本分析。


1. 最开始尝试的是多阶段的内容投递，如果检测到被分析后续阶段都断掉，得不到原文件其实就能很好地防住被分析了。


2. 考虑过在样本中加入一些妙妙提示词，来对模型进行误导


3. 后面考虑到如果能提高逆向成本，或者说逆向失败的代价，或许也是一种很好的办法（比如 agent 被成功欺骗后做出逃逸，或者直接让 agent 成为攻击链上的一环）

4. 最近在看一个叫 BLA 的项目，还在研究  https://github.com/qybaihe/bla/blob/main/docs/readme/README_zh.md

我会单独出几篇文章讲一讲这个项目好不好用，以及项目中的可取之处。（如果本地测试后验证真的能一定程度上避免样本被正确分析）



此外：

1. 一个样本只做静态分析很有可能会丢失大量关键信息（比如参数的传递，某些分支是否被正确运行。在我的实际测试中，一个被加过强壳的样本，只进行静态分析的时候很有可能卡死在某些关键节点。这个时候，如果没有合适的 skill 或者经验丰富的研究员进行指导，很耗费 token 和时间，也不失为一种阻碍分析的方法。）

2. 还有就是增肥，让 ida 这种分析器打不开，直接让样本分析胎死腹中了。（但是治标不治本，即使不用 ida，agent仍然能通过一些奇妙脚本对样本进行拆分）


于是我想到了一些神奇的组合技巧：

比如说，让分析者或者 agent 在静态层面看不到代码，只能通过动态进行调试。但是动态层面没有静态的辅助，又会耗费大量的时间。此外，在动态分析的过程中，如果还有进一步的解密，文件释放，又或者是多进程、多线程这种，也会极大延缓分析的进度。如果还有设置计划任务后 kill 本进程，一段时间后又拉起一个新的进程，那更是无比肥美。
